Introduction

Objectif du projet

L’objectif de ce projet est d’exécuter des programmes écrits dans un mini-langage, qui possède :

  • 26 variables globales (a, …, z) pouvant contenir des valeurs entières,
  • des conditionnelles (if),
  • des boucles while.

Et qui permet :

  • d’afficher le résultat d’une expression ou le contenu d’une variable,
  • de renvoyer une valeur à la fin de l’exécution.

La compilation

La compilation d’un programme consiste à convertir le code source, écrit dans un langage de haut-niveau (d’abstraction, donc plutôt compréhensible par les humains) en une suite d’instructions de bas-niveau, directement exécutables par la machine. On parle alors de programme exécutable.

Le langage C est un langage compilé, par opposition par exemple au Python, qui est interprété, c’est-à-dire que le code source est lu, décodé et exécuté uniquement à l’exécution.

Le processus de compilation se décline généralement en trois étapes :

  1. Analyse lexicale (appelée en anglais lexing, réalisée par le lexer) :

Le code source, sous forme de chaîne de caractères, est traduite en liste de symboles, que l’on appelle généralement tokens (mot anglais pour jetons). Ces tokens sont des unités lexicales, qui peuvent être des noms de variables, des nombres, ou encore des mots-clefs (if, while, return…).

NoteExemple

On se donne le code source suivant :

a = 1
if a
    print 2
else
    print 3
return a

La liste de tokens générée ressemblera à :
[ Var(a), Keyword(Assign), Expr(1), Keyword(If), Expr(a), Keyword(Print), Expr(2), Keyword(Else), Keyword(Print), Expr(3), Keyword(Endblock), Keyword(Return), Expr(a) ]

  1. Analyse syntaxique (parsing, réalisée par le parser) :

La liste de tokens est lue, et un arbre de syntaxe abstraite (AST) est construit à partir d’elle. Un AST permet de représenter le programme en mémoire sous une forme adaptée à son exécution. Un AST est en réalité un graphe orienté, dans lequel les sommets représentent les différentes instructions à exécuter, et les arcs représentent les transitions entre instructions.

L’arbre de syntaxe abstraite est utilisé en tant que langage intermédiaire entre le code source et le code machine, pour réaliser diverses opérations d’optimisation. Il sert ensuite de base pour la génération du code en langage machine qui composera le programme exécutable final.

Alternative : compilation en bytecode

Dans certains langages, comme le Java, le code produit n’est pas directement du code machine, mais un code en langage intermédiaire appelé bytecode, indépendant de l’architecture de la machine, et qui est interprété et exécuté par un programme appelé machine virtuelle. Cela a pour avantage notamment d’améliorer la portabilité du code compilé.

C’est cette approche que nous allons adopter pour ce projet. Nous allons écrire un programme qui prend en entrée un AST et exécute le code qu’il décrit.

Contenu de la base de code

Le code est organisée de la manière suivante :

  • Le dossier src contient les fichiers source (.c) et le dossier include les fichiers d’en-tête (.h).
  • Le dossier src/expressions contient les fichiers en lien avec l’évaluation des expressions arithmétiques. Ils sont fortement similaires à ceux du TP2, avec quelques différences.
  • Le dossier src/structures contient les implémentations des différentes structures de données, vues dans les TP précédents : listes à deux extrêmités, pile, file, et la structure qui contiendra les tokens de l’analyse lexicale t_prog_token_list. Vous n’avez rien à modifier dans ce dossier.
  • Le dossier file_io, contient le code d’un programme de lecture dans un fichier. Vous n’avez pas à le modifier.

Les principales fonctions à modifier, outre celles de src/expressions/expr., sont présentes dans le dossier src/program :

  • Les fichiers lexical.c et program.c contiennent diverses fonctions auxiliaires, que vous n’avez pas à modifier. program.c contient également le destructeur du type t_ast qu’il faudra compléter.
  • lexer.c contient les fonctions (à compléter en partie 3 du projet) de l’analyse lexicale.
  • parser.c contient les fonctions (à compléter en partie 2 du projet) de l’analyse syntaxique.
  • run.c contient les fonctions (à compléter en partie 1 du projet) d’exécution de l’AST.

Partie 1 : exécution d’un AST

L’objectif de la première partie du projet est d’écrire un programme qui prend en entrée un AST et exécute le programme qu’il représente.

Vous devez pour cela :

  • Compléter le fichier src/expressions/expr.c à la manière du TP2, afin de pouvoir évaluer des expressions en forme RPN (notation polonaise inversée, voir TP2). En particulier la fonction eval_rpn, qui doit cette fois gérer les variables dans les expressions. Vous devrez également écrire la fonction apply_op dans le fichier src/expressions/operator.c.
  • Bien comprendre les types représentant les AST, dans le fichier include/program/program.h. Pour cela, observez bien l’AST donné dans la fonction example du fichier src/main.c. Il s’agit de l’AST du code d’exemple de l’introduction (Figure 3). Vous pouvez vous aider de la fonction export_program_ast du fichier program.h.
  • Ecrire la fonction destroy_ast dans src/program/program.c, avec sa fonction auxiliaire destroy_statement. Cette fonction libère toute la mémoire allouée dynamiquement pour représenter un AST.
  • Ecrire la fonction run dans src/program/run.c, qui exécute le programme donné en entrée sous forme d’AST. Il est recommandé d’écrire cette fonction de manière récursive, avec une fonction auxiliaire run_aux.

Partie 2 : analyse syntaxique

L’objectif de la deuxième partie du projet est d’écrire la fonction de parsing, afin de convertir une liste de tokens (de type t_prog_token, dans une liste de type t_prog_token_list) en un AST.

Vous devez pour cela :

  • Bien comprendre la définition des t_prog_token dans le fichier include/program/lexical.h, ainsi que la liste de tokens de la fonction example dans src/main.c.
  • Comprendre la structure t_prog_token_list dans le fichier prog_token_list.h.
  • Compléter les fonctions parse et parse_aux dans le fichier src/program/parser.c.

Annexe : syntaxe du mini-langage

Instructions (statements)

  • Affectation (assignment) : la variable var reçoit le résultat de l’expression expr

    [var] = [expr]

    Exemple :

    a = 3

  • Affichage (print) : la valeur de l’expression expr

    print [expr]

    Exemple :

    print 2 * x + 3 * y

  • Conditionnelle “if” : si l’expression cond s’évalue à une valeur différente de 0, on exécute le programme prog_if_true, sinon le programme prog_if_false.

    if [cond]
    [prog_if_true]
else
    [prog_if_false]

    Exemple :

    if a == 0
        return 0
    else
        a = a + 1

  • Boucle “while” : tant que l’expression cond s’évalue à une valeur différente de 0, on exécute le programmme block.

    while [cond]
    [block]

    Exemple :

    while x != 0
        x = x - 1
        print x

Indentation

A chaque entrée dans un bloc de if, else ou while, on indente le code du bloc avec 4 espaces. Cette convention est importante si vous souhaitez écrire l’analyseur lexical.
