TP4 - Structures arborescentes

Introduction

On souhaite implémenter une base de données contenant des chaînes de caractères. On doit se munir des trois opérations suivantes :

  • Recherche : pour une chaîne \(s\) donnée, déterminer si \(s\) appartient à la base de données
  • Insertion : pour une chaîne \(s\) qui n’appartient pas à la base de données, ajouter \(s\) à la base de données
  • Énumération : lister toutes les chaînes qui appartiennent à la base données

On propose une première implémentation d’une telle base de données.

Dans le fichier src/database/database_array.c. Cette implémentation utilise un tableau dynamique, similaire à celui vu dans le TP1, dont l’implémentation est donnée dans src/structures/array.c.

  1. Compiler et exécuter le programme. La fonction main teste d’insérer un nombre \(n\) de chaînes entre 10 et 100000.

La fonction exécutée pour chaque test est la suivante :

    const string s = get_next_random_string();
    if (!is_in_database_array (&db, s))
        insert_in_database_array (&db, s);
    else
        denied++;
}

Partie 1 : Arbres binaires de recherche

Nous allons implémenter une structure de données plus efficace pour réaliser ces opérations.

Un arbre binaire (binary tree) est une structure récursive, qui peut être soit vide, soit composée d’une valeur et de deux sous-arbres binaires (possiblement vides).

Ici, l’arbre est \(T = (4, T_{left}, T_{right})\). Il contient la valeur \(4\) et deux sous-arbres \(T_{left} = (5, Empty, Empty)\) et \(T_{right} = (1, (9, Empty, Empty), Empty)\). Les noeuds notés \(\_\) indiquent des arbres vides.

Pour un arbre \(T = (v, T_{left}, T_{right})\), on appelle \(T_{left}\) le fils gauche et \(T_{right}\) le fils droit de T. Lorsque l’on voit un arbre comme un ensemble de noeuds, le noeud au sommet de l’arbre est la racine (root) de l’arbre. Les noeuds (nodes) dont les deux fils sont vides sont appelés des feuilles (leaf / leaves) et les autres des noeuds internes. Dans l’exemple de la figure Figure 1, la racine est le noeud contenant \(4\), et les feuilles les noeuds contenant \(5\) et \(9\).

Un arbre binaire de recherche (binary search tree) est une variété d’arbre binaire avec une propriété supplémentaire. Si l’arbre est égal à \(T = (v, T_{left}, T_{right})\), alors les valeurs contenues dans \(T_{left}\) sont inférieures ou égales à \(v\), et celles contenues dans \(T_{right}\) sont strictement supérieures à \(v\).

Pour insérer une valeur \(val\) dans un arbre binaire de recherche \(T\) :

  • Si \(T = Empty\), on y place un noeud \((val, Empty, Empty)\).
  • Si \(T = (v, T_{left}, T_{right})\) et \(val \leq v\), on insère \(val\) dans \(T_{left}\), sinon on l’insère dans \(T_{right}\).

Partie 2 : Arbres équilibrés AVL

Nous allons améliorer notre structure, en implémentant des opérations d’équilibrage, afin d’obtenir une structure d’AVL.

La hauteur d’un arbre binaire est la longueur du plus long chemin entre une feuille et la racine. Par convention, un arbre vide a une hauteur de \(-1\), un arbre \((v, Empty, Empty)\) est de hauteur \(0\), et un arbre \(T = (v, T_{left}, T_{right})\) a une hauteur \(h(T) = 1 + \max(h(T_{left}), h(T_{right}))\). Les arbres des figures Figure 1 et Figure 2 ont une hauteur de \(2\).

Le facteur d’équilibrage (balancing factor) d’un arbre \(T = (v, T_{left}, T_{right})\) est \(bf(T) = h(T_{left}) - h(T_{right})\). On dit qu’un arbre \(T = (v, T_{left}, T_{right})\) est équilibré si \(bf(T) \in \{-1, 0, 1\}\) et \(T_{left}\) et \(T_{right}\) sont équilibrés.

Définition

Les arbres AVL sont des arbres binaires de recherche qui appliquent des opérations de rotations à chaque insertion, afin de maintenir l’équilibre de l’arbre.

Règles

Après une insertion d’une valeur dans le fils \(T_{left}\) ou \(T_{right}\) d’un arbre \(T = (v, T_{left}, T_{right})\), on recalcule le facteur d’équilibrage de \(T_{left}\), \(T_{right}\) et \(T\), et on applique les règles suivantes :

  • Si \(bf(T) = -2\) :
    • Si \(bf(T_{right}) = -1\): rotation à gauche de \(T\)
    • Sinon si \(bf(T_{right}) = 1\): rotation à droite de \(T_{right}\) puis rotation à gauche de \(T\)
  • Sinon si \(bf(T) = 2\):
    • Si \(bf(T_{right}) = -1\): rotation à gauche de \(T_{left}\) puis rotation à droite de \(T\)
    • Sinon si \(bf(T_{right}) = 1\): rotation à droite de \(T\)
  • Sinon, on ne fait rien.

Il faut appliquer ces opérations en remontant le long du chemin entre la racine et le noeud où a eu lieu l’insertion.

Partie 3 (Bonus) : Arbres préfixes

Un arbre préfixe (en anglais trie, souvent prononcé [ˈtraɪ]) est une structure d’arbre spécialisée pour le stockage des chaînes de caractères.

On suppose que l’alphabet de base des chaînes de caractères contient \(M\) lettres. Chaque noeud contient un booléen is_present, initialement false, et un tableau table de taille \(M\) de pointeurs vers des arbres préfixes (initialement nuls).

Si l’on souhaite insérer la chaîne \(s\) dans l’arbre préfixe \(T\), alors :

  • Si \(s\) est vide, on donne true à T.is_present.
  • Sinon, \(s = s_0s_1\dots s_n\). On insère la chaîne \(s_1\dots s_n\) dans le fils table[s[0]] de T.

  2. Tester votre structure avec la fonction test_prefix_tree du fichier src/tests/test_structures.c. Visualiser l’arbre produit avec Mermaid.

  3. Décommenter l’appel à la fonction measure_prefix_tree_method dans la fonction main. Comparer le temps d’exécution des tests avec la structure d’arbre préfixe, par rapport aux tableaux et aux arbres AVL.
